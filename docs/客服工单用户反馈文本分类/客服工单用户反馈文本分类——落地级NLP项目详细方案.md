# 客服工单用户反馈文本分类：落地方案与实现边界

> 本文档用于说明业务问题、技术路线和后续演进。当前已实现内容以仓库代码、结果文件和 [`README.md`](../../README.md) 为准。

## 1. 业务目标

电商客服工单通常包含多个诉求，例如“物流未到、客服不回复、用户要求退款”。单标签模型只能保留一个结果，容易造成漏派部门和错误统计。本项目将反馈转换为多标签诉求，并进一步生成情感、优先级、SLA、责任部门、建议回复和复核状态。

## 2. 当前技术路线

```text
文本输入
  -> RF / FastText / BERT + LoRA
  -> 9 类独立概率
  -> 单标签阈值 + 全局置信度拒识
  -> 本地自动分流 / 可选外部推理 / 人工复核
  -> 情感分析 + 优先级规则 + 话术审批 + 工单落库
```

### 模型层

- RF：TF-IDF + OneVsRest，作为传统基线。
- FastText：多标签 `ova`，作为轻量神经网络基线。
- BERT：本地 `bert-base-chinese`，在 query/value 投影注入手写 LoRA，仅训练适配器和分类头。
- 训练使用 BCEWithLogitsLoss、`pos_weight` 和难例动态加权采样。

### 业务层

- `08-sentiment`：词典、否定词、程度词和规则组合，输出三类情感。
- `09-priority`：结合标签基础优先级、情感和升级信号输出 P0/P1/P2 与 SLA。
- `10-reply-recommend`：根据标签和优先级生成回复草稿；高风险或拒识工单强制人工审批。
- `11-ticket-kg`：统计标签共现，提供关联标签补全提示和风险组合告警。

## 3. 评估方式

除 Micro-F1、Macro-F1、Subset Accuracy、Hamming Loss 和逐标签 F1 外，系统还记录自动分流率、拒识率、人工复核率、平均置信度和推理延迟。阈值只在开发集上搜索，测试集只用于最终报告。

当前合成演示语料上的结果：

| 模型 | Micro-F1 | Macro-F1 | Subset Accuracy | 自动分流率 |
|---|---:|---:|---:|---:|
| RF | 0.6533 | 0.6536 | 0.3645 | 87.94% |
| FastText | 0.7597 | 0.7825 | 0.4694 | 83.53% |
| BERT + LoRA | 0.9175 | 0.9275 | 0.8365 | 89.88% |

这些数字用于验证当前链路和模型相对差异。数据是合成语料，不能直接当作真实业务上线指标。

## 4. 数据治理

`tools/build_dataset_v2.py` 通过模板家族分组、实体槽位隔离和短句覆盖构建数据，避免同一模板变体落入不同集合。旧版生成器存在模板级泄漏，不用于当前指标。

真实落地时应使用脱敏工单，按业务时间或会话/模板家族切分，双人标注并对分歧样本仲裁，再重新进行训练、校准和阈值标定。

## 5. 上线前工作

- 真实数据验证和线上分布漂移监控。
- LoRA、难例采样、拒识和外部推理的消融实验。
- 补充 pytest、CI、权限分级、审计脱敏和多实例 Redis 部署。
- 评估量化、蒸馏和剪枝的体积、延迟与效果权衡。
- 通过人工复核结果构建主动学习和周期性重训闭环。

本文不把尚未实现的双任务训练、ONNX/INT8、量化、蒸馏和剪枝写成当前成果；它们属于明确的后续路线。
