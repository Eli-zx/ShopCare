# ShopCare 改造说明

## 1. 改造背景

ShopCare 源于一个中文新闻单标签分类教学项目。本次改造将其转为电商客服工单多标签分类与智能分流平台，重点从“模型给出类别”推进到“系统给出可执行决策”。

## 2. 已完成改造

### 2.1 单标签改为多标签

- 任务从 10 类新闻单标签改为 9 类电商工单多标签。
- RF 使用 OneVsRest，FastText 使用 `loss=ova`，BERT 使用 9 维独立 sigmoid 输出。
- BERT 使用 BCEWithLogitsLoss 和按标签计算的 `pos_weight`，支持长尾标签。
- `invalid` 被定义为独占标签，其余标签可以组合。

### 2.2 三套模型统一对照

三套模型共用 `01-data` 数据格式、工具侧评估函数和统一推理字段，支持在同一页面对比模型结果：

| 模型 | 用途 |
|---|---|
| TF-IDF + OneVsRest 随机森林 | 传统可解释基线 |
| 多标签 FastText | 轻量文本分类基线 |
| BERT + 手写 LoRA | 主模型与复杂语义对照 |

### 2.3 从分类到业务闭环

新增情感分析、优先级/SLA、回复模板审批、标签共现风险分析、人工复核和工单看板。模型结果通过 `backend/common/pipeline.py` 编排，统一输出部门、优先级、建议回复和复核状态。

### 2.4 工程化服务

- 用 FastAPI 统一封装模型和业务接口，入口为 `backend/main.py`。
- 使用 `backend/common/model_registry.py` 实现模型懒加载、可用性探测和降级。
- 使用 JWT 完成登录认证，Redis 支持限流、缓存和令牌撤销记录。
- MySQL 不可用时降级为内存存储，Redis 不可用时降级为进程内实现，并通过 `/health` 暴露状态。
- 前端采用零构建的原生 HTML/CSS/JavaScript，不依赖 npm 或 Chart.js。

### 2.5 数据质量治理

早期合成语料存在模板子句跨集合泄漏，导致指标虚高。当前 `tools/build_dataset_v2.py` 使用模板家族分组、槽位隔离和短句覆盖重新构建数据，`01-data/split_manifest.json` 保存检测结果。当前测试子句在训练集中的原样出现比例为 0%。

## 3. 关键工程决策

- 多标签任务不使用 softmax，避免强制 9 个标签互斥。
- 双阈值拒识用于控制错派：标签激活阈值决定是否有明确诉求，全局阈值决定整体结果是否足够可靠。
- 置信度在开发集上校准后再用于展示和拒识；RF 使用等频分箱，FastText 使用 Platt 校准。
- 外部推理服务只作为拒识后的可选兜底，默认关闭，避免引入额外运行成本。
- 三个阶段都有同名 `config.py`，后端使用独立模块名加载，自检脚本使用独立子进程，避免 Python 模块缓存串扰。

## 4. 当前状态与边界

已实现：数据构建与检查、RF/FastText/BERT 训练与推理、情感、优先级、话术、知识图谱、FastAPI 服务、认证、降级、前端工作台、复核队列和看板。

未实现：05/06/07 目录对应的量化、蒸馏和剪枝；正式单元测试与 CI；前端权限分级；生产级多实例限流和审计归档。
